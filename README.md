# منصة نِعْمَة (Nemaa) — تَذَكَّرْ لِتَشْكُرْ 🌿

منصة ويب روحية وتدبرية متكاملة باللغة العربية، مصممة لاستشعار نعم الله الباطنة والظاهرة وتدبرها عبر بطاقات تفاعلية أنيقة وتأملات ملهمة، لترسيخ الحمد والامتنان اليومي.

---

## 🎨 الهوية البصرية والتصميم (UI/UX)
- **فلسفة التصميم**: واجهة هادئة، روحية، وبسيطة (Minimalist & Spiritual) مستوحاة من المخطوطات والزخارف الإسلامية المعاصرة.
- **لوحة الألوان المعتمدة**:
  - خلفية كريمية رملية دافئة: `#FDFBF7`
  - أخضر زيتي عميق: `#2C4A3E`
  - لمسات ذهبية / عنبرية: `#D4AF37`
  - نصوص فحمية واضحة ومريحة للقراءة: `#2D3748`
  - وضع سكينة الليل (Dark Mode) المخصص للتأمل المسائي الهادئ.
- **الخطوط العربية (Google Fonts)**:
  - العناوين والتأملات: **Reem Kufi** و **Amiri**
  - عناصر واجهة المستخدم: **Cairo** و **Tajawal**

## ✨ المميزات والخصائص التفاعلية

### 1. مولد النعم الذكي والتصنيفات (Blessing Generator)
- **عرض عشوائي سلس**: زر بارز «نِعْمَةٌ جَدِيدَةٌ» مع تأثيرات تنقل انسيابية ومفاتيح اختصار (زر المسافة Spacebar أو الأسهم).
- **تصنيفات رئيسية متكاملة مع عدادات حية**:
  - 🌿 **نعم باطنة وخفية**: كستر الذنوب، لطف المقادير، نعمة النسيان للآلام، وانصراف الشر دون علمك.
  - 🩺 **الصحة والجسد**: العافية بلا تنبيه، نبض القلب، نعمة البصر، المفاصل وجهاز المناعة.
  - 🕌 **نعم إيمانية وروحية**: الهداية للإسلام، حلاوة السجود، مواساة القرآن، والراحة في الصلاة.
  - 👨‍👩‍👧‍👦 **العلاقات والأهل**: دعاء الوالدين، البيت الآمن، الصديق الصالح، والكلمة الطيبة.
  - ☀️ **نعم يومية بسيطة**: رشفة الماء البارد، قوت اليوم، الأمان في السرب، ورائحة المطر.
- **شواهد موثقة**: كل نعمة مرفقة بآية قرآنية أو حديث نبوي شريف مع التخريج والسورة ورقم الآية.

### 2. تفاعلات الحمد والامتنان (Gratitude Interactions)
- **زر «الْحَمْدُ لِلَّهِ» التفاعلي**:
  - انبعاث جزيئات ذهبية وخضراء (Confetti Particles).
  - نغمة رنين روحية هادئة مبرمجة عبر **Web Audio API**.
  - ظهور عبارات حمد وتسبيح مهدئة للقلب (مثل: *«لَئِن شَكَرْتُمْ لَأَزِيدَنَّكُمْ»*, *«بالشكر تدوم النعم»*).
- **عداد الحمد اليومي وتتبع الاستمرارية (Streak Tracker)**:
  - حساب عدد مرات الحمد والتأمل يومياً وحفظها تلقائياً.
  - شارات تقديرية للأوراد والحمد المستمر (*شاكر*، *ذاكر*، *حامدٌ وممتن*).

### 3. المشاركة والتحميل كصورة مصممة (Social & Sharing)
- **تحميل البطاقة كصورة**: توليد صورة عالية الدقة (1080×1350) بضغطة زر واحدة صالحة للمشاركة الفورية على حالات واتساب وإنستغرام، متضمنة الشعار والنص والآية.
- **روابط مشاركة سريعة**: مشاركة مباشرة عبر واتساب، تيليجرام، منصة إكس (Twitter)، مع نسخ النص بضغطة زر.

### 4. التخصيص والمفضلة والتدوين الخاص
- **المفضلة (Bookmarks)**: إمكانية حفظ النعم المفضلة في قائمة محلية والرجوع إليها أو تصفيتها في أي وقت.
- **إضافة نعمة خاصة (Personal Blessings)**: نموذج يتيح لك كتابة نعم وتدبرات من حياتك الشخصية وإدراجها فوراً في دورة النعم وظهورها بوسم *«نعمة خاصة بك»*.
- **بحث وتصفح شامل**: نافذة بحث فورية عن أي كلمة، معنى، أو وسم بين جميع النعم.

### 5. مؤثرات صوتية وبيئية للسكينة (Ambient Soundscape)
- مولد أصوات طبيعية وروحية خفية مدمج يعمل بدون إنترنت (Offline Procedural Web Audio):
  - 🌧️ مطر هادئ (Light Rain)
  - 🍃 نسيم عليل وسكينة (Gentle Breeze)
  - 🐦 تغريد فجر خافت (Dawn Birds)
  - 🕊️ سكون وتأمل بتردد 432Hz

## 🚀 التشغيل والبناء

```bash
npm install
npm run dev       # للتطوير: http://localhost:5173
npm run build     # للنسخة الإنتاجية
npx oxlint src     # فحص الكود (oxlint) — اكتب src حتى لا يفحص الملفات المبنية
```

> ⚠️ **ابنِ دائماً بـ `npm run build` وليس `vite build` وحده.** الأمر الكامل يشغّل خطوتي
> `prebuild` و`postbuild` اللتين تنسخان الناتج إلى جذر المستودع ومجلد `docs/`، وهما ما يخدمه GitHub Pages.
> بدونهما يبقى الموقع على النسخة القديمة أو يتعطل.

## 🌐 النشر

الموقع منشور على GitHub Pages من الملفات المبنية الموجودة في المستودع نفسه:
`https://ahmedmootx-sys.github.io/NEMAA/`. خطوات أي تحديث:

1. عدّل الملفات ثم شغّل `npm run build`.
2. ارفع كل التغييرات (بما فيها `assets/` و`docs/` و`index.html` و`sw.js` الناتجة عن البناء) إلى فرع `main`.
3. بعد دقيقة أو دقيقتين افتح الموقع وتأكد. التطبيق يتحدث عند أول فتح بعد النشر
   (التنقل يعتمد الشبكة أولاً)، أما من يملك التطبيق مفتوحاً فيأخذ التحديث عند فتحه التالي.

**ترتيب مهم عند ترقية الأمان لأول مرة:** انشر التطبيق الجديد **أولاً** ثم شغّل `01_migration.sql`.
العكس يجعل النسخة القديمة تعرض «تم النشر» بينما الخادم رفض الكتابة. التفاصيل في `ROLLOUT_AR.md`.

## 🔐 الأمان ونموذج الملكية

- مفتاح `anon` في الكود عام بطبيعته؛ الحماية الحقيقية في سياسات قاعدة البيانات (RLS) لا في إخفاء المفتاح.
- كل نعمة تُنشر يولّد لها التطبيق **رمز مالك** عشوائياً (128 بت) يُحفظ في جهاز كاتبها وفي حسابه إن سجّل الدخول.
  الخادم يحفظ **بصمة SHA-256** للرمز فقط. التعديل والحذف لا يتمان إلا بإثبات الرمز عبر دوال RPC.
  لا أحد يستطيع الكتابة المباشرة في الجداول.
- **ضياع الرمز = ضياع حق التعديل.** مسح بيانات المتصفح بدون حساب مسجّل يفقد صلاحية تعديل نعمك
  (النعمة نفسها تبقى منشورة). التسجيل بحساب يحفظ الرموز في جدول `user_backup` ويعيدها على أي جهاز.
- المدير = صف في جدول `admins` مرتبط ببريد حسابه. استخدم كلمة مرور قوية وفعّل التحقق الثنائي لهذا الحساب.
- فلتر الألفاظ في التطبيق يعمل في الواجهة فقط (الخادم يتحقق من الأطوال والمعدل فقط)، وهو يمنع النشر العفوي لا الهجوم المتعمد.
- حدود معدل على الخادم: 20 نعمة/دقيقة، 20 بلاغاً/دقيقة، 10 ملاحظات/دقيقة.

## 🗄️ قاعدة البيانات (Supabase)

- `supabase/01_migration.sql`: يُشغَّل مرة واحدة من **SQL Editor** بعد استبدال `PUT_ADMIN_EMAIL_HERE` ببريد حساب المدير.
  آمن للتكرار (idempotent) ويرفض العمل إذا بقي النص الافتراضي أو كان البريد غير مسجّل.
- `supabase/02_rollback.sql`: يعيد السياسات القديمة. يترك الجداول والدوال الجديدة كما هي حتى يستمر التطبيق الجديد في العمل.
  **لا تُرجع كود التطبيق وحده** بعد الترحيل؛ ارجع بالـ SQL فقط.
- **قائمة ضبط لوحة Supabase** (يدوياً، لا يمكن من الكود):
  - Authentication → URL Configuration: اجعل *Site URL* = `https://ahmedmootx-sys.github.io/NEMAA/` وأضفه إلى *Redirect URLs*.
  - كلمة مرور قوية + MFA لحساب المدير.
  - راجع Authentication → Providers → Email (تأكيد البريد) بما يناسب سياستك.
  - فعّل النسخ الاحتياطي إن كانت خطتك تدعمه، وراقب Reports → Database.

## 🔔 الإشعار اليومي

يُرسل عبر OneSignal من GitHub Actions (`.github/workflows/daily-push.yml`).

| ما تحتاجه | أين |
|---|---|
| `ONESIGNAL_REST_API_KEY` (سر) | GitHub → Settings → Secrets and variables → Actions → **Secrets** |
| `ONESIGNAL_APP_ID` (سر، اختياري) | نفس المكان، وله قيمة افتراضية في السكربت |
| `PUSH_MODE` (متغير، اختياري) | نفس المكان تبويب **Variables** |

- `PUSH_MODE` غير موجود أو `broadcast` (الافتراضي): إشعار واحد للجميع الساعة 06:00 UTC.
- `PUSH_MODE=slots`: يحترم الوقت الذي اختاره كل مستخدم بتوقيته المحلي (صباحاً 08:00، ظهراً 13:00، مساءً 18:00،
  قبل النوم 22:30، عشوائي نهاري 09:00–20:00، أو وقت مخصص مقرَّب لأقرب ربع ساعة).
  يرسل نحو 101 طلباً في اليوم (شريحة لكل وقت)، والشرائح الفارغة تُتجاوز دون خطأ.
- **جرّب قبل التفعيل:** Actions → NEMAA Daily Blessing Push → Run workflow مع `dry_run=true` ليطبع الطلبات دون إرسال.
- **تنبيه:** وضع `slots` مختبَر مقابل خادم OneSignal وهمي فقط؛ لم يُجرَّب على OneSignal الحقيقي.
  فعّله، وراقب أول يوم على هاتفك قبل الاعتماد عليه. وثائق OneSignal لا تذكر ما يحدث إن كان وقت التسليم قد فات في منطقة زمنية معيّنة.
- على آيفون لا يعمل الاشتراك في الإشعارات إلا بعد إضافة التطبيق للشاشة الرئيسية (التطبيق ينبّه المستخدم بذلك).

## 💓 إبقاء Supabase نشطاً

المشروع المجاني يُوقَف بعد 7 أيام بلا نشاط. `.github/workflows/keepalive.yml` يرسل قراءة خفيفة كل 3 أيام.
- GitHub **يوقف الجداول الزمنية تلقائياً** في المستودعات التي لا نشاط فيها 60 يوماً؛ إن حدث ذلك ستصلك رسالة بريد،
  وتعيد تفعيله من تبويب Actions بضغطة واحدة (أو بأي تعديل صغير في المستودع).
- إن فشل التشغيل (علامة حمراء) فغالباً المشروع متوقف: افتح لوحة Supabase واضغط **Restore project**.

## 🧰 استكشاف الأخطاء

| العَرَض | السبب المرجّح | الحل |
|---|---|---|
| «قيد التحديث» عند النشر | لم يُشغَّل `01_migration.sql` بعد | شغّله (بعد نشر التطبيق) |
| الموقع لا يتغير بعد النشر | لم تُرفع ملفات البناء، أو الكاش | تأكد من `npm run build`، وأعد فتح التطبيق مرتين |
| شاشة «حدث خطأ غير متوقع» | خطأ برمجي غير متوقع | زر «إصلاح وإعادة التحميل» (لا يمس بياناتك)؛ ثم أرسل الرسالة من «Technical details» |
| التطبيق كله لا يعمل فجأة | مشروع Supabase متوقف | Restore project من اللوحة |
| لا تصل الإشعارات | لم يُسجَّل `ONESIGNAL_REST_API_KEY`، أو المستخدم لم يشترك | راجع سجل تشغيل الـ workflow |
| صفحة بيضاء بعد `vite build` | بُني بدون `postbuild` | شغّل `npm run build` |

## ⚠️ حدود معروفة

- عنوان النعمة هو المفتاح الأساسي في جدول `blessings` (لا يوجد `id`): لا يمكن نشر نعمتين بنفس العنوان.
  تغييره يحتاج ترحيلاً حذراً للبيانات الحية ولم يُنفَّذ.
- عدّاد «الحمد» تقريبي ويمكن تضخيمه؛ لا تعتمد عليه في أي حساب مهم.
- النعم التي أعادها المدير من الأرشيف، وثلاث نعم قديمة، بلا مالك: لا يستطيع أحد تعديلها غير المدير.
- الإشعارات التي كانت مخزّنة في جدول `reports` القديم لا تُسلَّم بعد الترحيل.
- لم يُختبر شيء على GoTrue وRealtime وبيئة الإنتاج الحقيقية؛ الاختبارات على نسخة طبق الأصل من السياسات.
